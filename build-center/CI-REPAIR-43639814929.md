# Integrate the current SuSFS source before control overlays and tests

Run 43639814929 passed repaired locked ARM64 userspace, Guard6, ReSuSFS and
all earlier kernel source/C gates. Its complete merge evidence identified
two remaining conflicts: the new official SUS_PATH UID bitmap versus the
already applied local UID guard, and new legacy SELinux wrappers versus the
native SukiSU profile that never imported that manual handler family.

The official source delta is now integrated immediately after the audited
priority backport and before UIDGate, runtime controls and exact-C tests.
The old baseline release header is checked first. The merged release header
is then bound to the immutable source plan and measured source-update receipt,
and reverified in final compiled artifact checks. The priority overlay is
validated before the merge, then its changed functions are recorded from the
new pinned source; its real semantic and negative-control tests run afterwards.

Only the exact added legacy SELinux default/force wrappers are excluded when
they are the sole services.c delta. Any unrelated services.c change still
requires a merge and review. Native SukiSU SELinux source identity remains
mandatory; legacy parallel state is explicitly rejected. An added explanatory
SELinux heading cannot reintroduce a deliberately absent legacy state block.

The new 0x55554 SUS_PATH UID command is wired into the native SukiSU dispatcher
and its package refresh runs after throne tracking outside fsnotify locks.
Existing UID and runtime controls wrap the updated upstream path predicate.
Final-source exact-C tests cover the actual predicate and bitmap, multiuser
normalization, invalid/system UIDs, FUSE/null paths, balanced RCU, four negative
controls, and both dispatcher CONFIG states. The priority C tests retain all
four existing fault controls and use the real new shared range constants.

A local replay using the actual CI source versions merged successfully before
the overlays. All seven priority functions matched their expected old/new
upstream bodies. Both sets of exact-C semantic tests passed with all negative
controls rejected. Kernel compilation and strict KMI/CRC still require the
subsequent complete CI run; no device runtime or boot claim is made.
