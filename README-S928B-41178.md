# S928B EZJ1 · SukiSU 41178 preview · latest SUSFS

This isolated branch builds the requested version 41178 for
`S928BXXS6EZJ1-EUX-android14-6.1.162`. SukiSU's official translation PR1044 has
merge commit `1c9cca42f8049227d4eea20ab3979db3c5662a7d`, with 3993 commits:
`40000 + 3993 - 2815 = 41178`. This is the official PR preview, while main at
`3af6085d0d26e73ffd1a3e7b34362435dcfb5a03` reports 41176. Their kernel, UAPI,
userspace and Cargo sources are identical; only two translation files differ.

The latest SUSFS gki-android14-6.1 source is resolved once at runner startup.
On 2026-11-11 it reports v2.4.0 at
`69b8e734920b8f9ed885ab8d112969719698e242`. Since `a2165b6f`, only the
official KernelSU integration patch changed. SukiSU retains the independently
ported native SELinux/manual-hook integration; its kernel/CLI inputs are
checked against the new immutable plan and strict build gates.

The previous audited feature profile remains: KPM 0.14.0 / ABI2, DroidSpaces,
Gunyah Adaptive and Reclaim, ZRAM, BBG, OverlayFS, OPEN_REDIRECT, UIDGate,
all four Runtime controls, Priority UID, and HIDDEN_NAME-v2. CPU/PID limits
remain disabled. All Samsung Strict KMI/DLKM CRC checks remain mandatory.

The controller uses the `f269b2d3` builder template and never reuses historical
compilation receipts for the new sources. Kernel and ARM64 userspace are rebuilt
together. The matching ReSuSFS module retains the restored original SUSFS UI
and separate Runtime addition. Publication requires successful build jobs and
the actual AnyKernel3 payload, target-firmware receipt and Image-bound evidence.

Entry point: `.github/workflows/build-center.yml` on this isolated branch.
The branch has an explicit 41178 pin; no main-branch workflow, scheduled job,
application release, phone module, kernel flash or reboot is modified by this
source update. The resulting kernel remains a prerelease until device testing.

After three GitHub startup failures before any job was assigned, this branch
also provides a deterministic expansion of the five local single-job workflows.
The original graph remains in `build-center/ci/compat/build-center-41178-reusable.yml`;
`ci/inline_workflows.py` expands the same 132 steps into seven direct jobs,
retaining dependencies, conditions, input types/defaults and effective permissions.
The workflow-source files and all kernel gates remain unchanged. This is a
controlled alternative for GitHub's startup phase, not a proven diagnosis of the
internal service error. Constant profile conditions are retained deliberately;
actionlint's constant-condition style diagnostic can be filtered independently
from all other diagnostics for this generated file.
